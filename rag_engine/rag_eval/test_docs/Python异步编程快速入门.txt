Python 异步编程快速入门

一、为什么需要异步编程

在传统的同步编程模型中，程序按顺序逐行执行。当遇到 I/O 操作（如网络请求、数据库查询、文件读写）时，程序会阻塞等待操作完成，期间 CPU 处于空闲状态。对于需要处理大量并发请求的 Web 服务器来说，这种等待是对系统资源的严重浪费。异步编程通过"挂起"等待中的任务并切换到其他任务来充分利用 CPU 时间，从而在单线程内实现高并发。

二、核心概念：协程

协程（Coroutine）是异步编程的基本执行单元。可以把它理解为一个可以"暂停和恢复"的函数。当协程遇到 await 表达式时，它将控制权交还给事件循环，让其他协程有机会执行。被暂停的协程在等待的操作完成后会被自动唤醒，从暂停点继续向下执行。

一个厨师同时看着三个灶台的比喻非常形象：厨师把水烧上（await），不等水开就去切菜（切换协程），切完菜回来正好水开了。整个过程只有一个厨师（单线程），但三个灶台上的菜都在推进。

三、Python 异步编程的核心语法

async 和 await 是 Python 异步编程的两个关键字。用 async def 声明的函数会返回一个协程对象，必须通过 await 关键字或事件循环来执行。普通函数中不能使用 await，只能在 async def 声明的函数中使用。

示例代码：

async def fetch_data(url):
    async with httpx.AsyncClient() as client:
        response = await client.get(url)
        return response.json()

async def main():
    data = await fetch_data("https://api.example.com")
    print(data)

asyncio.run(main())

四、异步生成器和流式输出

异步生成器是 Python 异步编程中的高级特性，通过 async def + yield 语法定义。它结合了协程的暂停能力和生成器的迭代能力，每产出一次值就暂停一次，等待调用方通过 async for 逐个消费。在 AI 应用开发中，异步生成器是实现流式输出的关键技术手段——LLM 每生成一个 token 就通过 yield 推送给前端，用户看到的是实时逐字出现的"打字机效果"，而不是等 5 秒后一次性出现完整回答。

FastAPI 的 StreamingResponse 类接收一个异步生成器，将其作为 SSE（Server-Sent Events）流式响应发送给浏览器。SSE 是一种基于 HTTP 的单向通信协议，格式简单——事件类型（event）和数据（data）用纯文本行表示，两条消息之间用空行分隔。

五、异步 vs 多线程

异步编程和多线程都是处理并发的技术，但工作方式不同。多线程通过操作系统的调度在多个线程间切换，每个线程有独立的调用栈，切换由操作系统控制。异步编程在单线程内通过事件循环管理多个协程，切换由程序控制（在 await 处主动让出控制权）。

异步编程的优势在于没有线程切换的开销，没有锁竞争问题，更适合 I/O 密集型任务。对于计算密集型任务，异步编程没有优势，应该使用多进程或将计算任务交给线程池

六、Python 异步生态

httpx 是目前 Python 生态中最推荐的异步 HTTP 客户端，它同时支持同步和异步 API。在 FastAPI 项目中，推荐使用 httpx.AsyncClient 进行外部 HTTP 调用，因为 FastAPI 本身就是基于异步事件循环构建的，使用同步的 requests 库会在等待 HTTP 响应时阻塞整个线程。

aiosqlite 是 SQLite 的异步封装，允许在协程中执行 SQL 查询而不阻塞事件循环。在 LangGraph 的 AsyncSqliteSaver 中，aiosqlite 负责将对话状态异步持久化到 SQLite 数据库中。

七、FastAPI 中的异步实践

FastAPI 框架原生支持异步路由处理函数。用 async def 定义的路由函数会自动在事件循环中执行，不需要额外的线程池。但需要注意：不要在 async 路由函数中调用阻塞的同步函数，这会阻塞整个事件循环。对于不得不调用同步函数的情况，可以将其包装在 asyncio.to_thread() 中，让它在单独的线程中执行。

依赖注入（Depends）同样支持异步依赖函数。如果依赖函数是 async def 声明的，FastAPI 会自动等待其完成后再注入。这种设计使得可以在依赖中执行异步的数据库查询、配置加载等操作。
