# RAG（检索增强生成）技术详解

## 一、什么是 RAG

RAG 是一种将外部知识检索与大模型生成能力相结合的技术框架。传统大语言模型（LLM）的知识来源于训练数据，存在三大问题：一是训练数据有时效性限制，无法获取最新信息；二是在特定细分领域知识不足；三是容易产生"幻觉"，编造不存在的事实。RAG 通过在生成回答之前先从外部知识库中检索相关信息，将检索到的文档片段作为上下文提供给大模型，从而显著提升回答的准确性和可靠性。

## 二、RAG 的核心工作流程

RAG 系统的工作流程分为两个主要阶段：

第一阶段是离线索引阶段。首先将文档进行预处理，包括格式解析、文本清洗等。然后通过文本分块器（Text Splitter）将长文档切分成适当大小的文本块（Chunk），每个块通常为 300 到 800 个字符。分块时需要考虑重叠（Overlap），一般设置为块大小的 10% 到 20%，避免在块边界处切断重要的语义单元。分块完成后，使用嵌入模型（Embedding Model）将每个文本块转换为高维向量（Vector），常用的嵌入模型包括 OpenAI 的 text-embedding-3、阿里云的 text-embedding-v4 等。这些向量被存储到向量数据库（Vector Database）中，如 ChromaDB、Milvus、FAISS 等。

第二阶段是在线检索与生成阶段。当用户提出问题时，首先使用同一个嵌入模型将问题转换为向量，然后在向量数据库中执行相似度搜索（Similarity Search），找到与问题向量最相似的 Top-K 个文档块。为了提高检索质量，现代 RAG 系统通常采用混合检索策略——同时使用向量检索（语义匹配）和 BM25 检索（关键词匹配），通过 RRF（Reciprocal Rank Fusion）算法融合两种检索结果。检索到的文档块经过重排序（Reranking）后，与用户问题一起组合成提示词模板（Prompt Template），发送给大语言模型生成最终回答。

## 三、RAG 的关键技术组件

1. 文本分块策略：分块大小和重叠率直接影响检索效果。块太大则信息密度低，检索精度下降；块太小则信息碎片化，失去上下文。2025 年行业共识推荐 400 到 600 token 作为通用基线。分块时采用递归字符分割器（RecursiveCharacterTextSplitter），按段落、换行、句号、空格的优先级顺序进行切割，确保块边界落在自然语义单元的分界处。

2. 嵌入模型：嵌入模型的作用是将文本转换为向量表示。选择嵌入模型时需要考虑其对中文的支持能力、向量维度和推理速度。阿里云的 text-embedding-v4 支持 1024 维向量输出，在中英文混合场景下表现优秀。向量的余弦距离是衡量语义相似度的核心指标——距离越小表示语义越相近。

3. 向量数据库：向量数据库是 RAG 系统的存储和检索核心。ChromaDB 作为轻量级嵌入式向量数据库，适合开发和小规模部署，支持本地持久化和元数据过滤。Milvus 是面向生产环境的分布式向量数据库，支持十亿级向量检索和 GPU 加速。从 ChromaDB 迁移到 Milvus 时，核心检索 API 保持一致，主要差异在部署架构层面。

4. 重排序模型：检索阶段返回的 Top-K 文档不一定都能直接用于回答。重排序模型（如 BGE-Reranker、Cohere Rerank）对每个查询-文档对进行更精细的相关性打分，过滤掉低分文档。Cross-Encoder 架构的重排序模型虽然比双塔模型慢，但精度更高，适合在最后阶段对少量候选文档进行精排。

5. 提示词工程：RAG 系统的提示词需要明确告诉大模型"只使用提供的上下文信息回答问题"、"如果上下文不足以回答，请诚实说明"。好的提示词能显著降低幻觉率。

## 四、RAG 的常见优化方向

查询改写（Query Rewriting）是多轮对话场景下的重要优化。当用户使用代词或省略说法时（如"它有什么特点"），需要结合历史对话将查询改写为完整形式（如"LangGraph 有什么特点"），否则向量检索无法匹配到相关文档。

混合检索融合了语义匹配和关键词匹配的优势。向量检索擅长找"意思相近"的内容，但对专有名词和精确匹配不够敏感。BM25 关键词检索基于 TF-IDF 算法，对专有名词和编号非常有效。两者通过 RRF 算法融合，通常向量检索权重设为 0.6，BM25 权重设为 0.4。

检索后处理包括后置过滤和重排序两层。后置过滤利用向量相似度分数剔除明显不相关的文档，重排序则对剩余文档做精细打分。经过这两层后，通常只有 3-5 个最相关的文档块进入最终的回答生成阶段。

## 五、RAG 与微调的区别

RAG 和模型微调（Fine-tuning）是两种不同的知识增强方式。RAG 通过在推理阶段动态检索外部知识来增强回答，优点是知识更新方便（增加文档即可），不需要重新训练模型。微调则是通过训练数据更新模型参数，让模型"学会"特定领域的知识和行为模式，优点是一次训练后可反复使用，推理速度不增加额外开销。

在实际应用中，RAG 更适合知识频繁更新的场景（如政策法规、产品文档），微调更适合需要模型深度理解特定领域规律或风格的场景。许多企业级系统采用 RAG + 微调的混合方案：用微调让模型掌握领域基础，用 RAG 提供最新、最精确的参考信息。
